# YOLOv5WithClassification 訓練問題解決方案

## 🎯 問題診斷結果

### 日誌分析發現
- **訓練初期正常**：模型正在學習，檢測和分類任務都有進展
- **中期表現良好**：Epoch 139 時 mAP50 達到 27.3%，分類準確率 59.67%
- **後期梯度爆炸**：出現 `RuntimeError: Function 'ConvolutionBackward0' returned nan values`

### 根本原因 ⚠️ **更新分析**
1. **🔥 記憶體幾乎滿載**：31.9GB/32GB = 99.7% 使用率 - **主要原因**
2. **🔥 梯度計算空間不足**：無足夠記憶體進行動態分配
3. **梯度爆炸**：記憶體壓力導致數值計算異常
4. **學習率調度不當**：固定學習率在後期造成不穩定
5. **批次大小過大**：128 批次大小消耗過多記憶體

## 🛠️ 解決方案

### 1. 🚨 記憶體優化訓練命令 (推薦)
文件：`memory_optimized_training_commands.txt`
- **緊急記憶體優化**：批次大小 128 → 16
- **混合精度訓練**：添加 `--amp` 參數
- **記憶體目標**：31.9GB → <16GB (50% 使用率)

### 2. 穩定訓練命令 (備選)
文件：`stable_training_commands.txt`
- 使用改進的超參數配置
- 添加餘弦退火學習率調度 (`--cos-lr`)
- 調整批次大小降低記憶體壓力

### 2. 自定義超參數文件
文件：`data/hyps/hyp.stable_training.yaml`

#### 關鍵改進：
- **梯度剪裁**：`grad_clip: 10.0` - 防止梯度爆炸
- **降低學習率**：`lr0: 0.005` - 提高訓練穩定性
- **增加暖身期**：`warmup_epochs: 5.0` - 更平滑的訓練啟動
- **平衡損失權重**：降低各項損失權重避免過度優化
- **標籤平滑**：`label_smoothing: 0.05` - 提高泛化能力

### 3. 批次大小調整
```
模型類型            原始    穩定版    原因
Backbone & P4/P5:   64  →   32      降低記憶體使用，提高穩定性
P3:                128  →   64      較小模型仍可使用較大批次
```
